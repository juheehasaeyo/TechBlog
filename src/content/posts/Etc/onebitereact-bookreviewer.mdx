### ❗ 여기서 문제
1. let, var, const의 차이? p,16, 66 참고
let은 var와 달리 중복 선언이 불가능,
let과 var는 변수지만 const는 상수, 
변수는 선언과 동시에 할당하는 초기화 과정이 필요치 않지만 상수는 필요함

2. 함수 Number와 parseInt의 차이? p. 29 참고
Number는 문자열을 숫자로 변환해서 반환. 
// 숫자가 아닌 문자를 포함한 문자열은 NaN을 반환함
let strA = '10';
let strB = '10개';

let numA = Number(strA);
let numB = Number(strB);

console.log(numA); // 10
console.log(numB); // NaN

parseInt는 괄호 안에 두 개의 값을 콤마로 구분해서 전달하는데, 첫 번째 값은 변환하려는 문자열이고 두 번째 값은 진수.

// 문자열이 숫자가 아닌 문자로 시작하면 NaN을 반환함
let str = '화이팅 2026';
let num = parseInt(str, 10); 

console.log(num); // NaN

--------
var는 함수 스코프, let과 const는 블록 스코프

3. 비교연산자 == 과 ===의 차이? p.36
== 는 값만 비교할 뿐 자료형은 비교하지 않는다.
let numA = 2;
let numB = 2;
let numC = '2';

console.log(numA === numB); // true
console.log(numB === numC); // false
console.log(numA == numC); // true

4. 인수와 매개변수의 차이? p.53
인수는 함수를 호출하면서 넘겨주는 값이고 매개변수는 함수에서 넘겨받은 인수를 저장하는 변수.
즉, 인수는 '값' 매개변수는 그 값을 저장할 '변수'로 생각하면 이해가 쉽다.

funtion getArea(width, height) {
let area = width * height;
console.log(area);
}
getArea(10, 20);
에서 10과 20이 인수, width와 height가 매개변수

6. truthy falsy 단락평가
falsy한 값이란 boolean 자료형의 false값은 아니지만, 거짓과 같은 의미로 쓰이며 조건식에서 거짓(false)로 평가되는 것
falsy 값은 다음 7가지이다.
- undefined
- null
- 0, -0
- NaN
- "" (빈 문자열)
- 0n (BigInt)

단락평가 부분을 읽으며 프로젝트에서 얕은 비교와 단락평가에 대해 찾아보면 좋겠다는 리뷰를 받은 적이 있어서 기억났다. 해당 부분과 함께 다시 리마인드 해보자

### 단락 평가 (Short-circuit Evaluation)

논리 연산자 &&는 단순히 boolean이 아니라 "값"을 반환한다.

A && B
- A가 falsy → A 반환 (뒤를 평가하지 않음)
- A가 truthy → B 반환

즉, A가 false면 B를 볼 필요가 없기 때문에 A를 그대로 반환하고, A가 true면 B까지 평가한 뒤 B를 반환한다.

### 프로젝트에서의 문제 상황

다음과 같은 코드를 사용하고 있었다.
```tsx
{isSoldOut && <SalesBadge isSoldOut={isSoldOut} />}
```

이 코드는 isSoldOut이 truthy일 때만 컴포넌트를 렌더링한다.
하지만 isSoldOut이 undefined인 경우, 기대와 다르게 컴포넌트가 렌더링되지 않았다.

왜 이런 일이 발생했을까?!
```tsx
isSoldOut && <SalesBadge />
```

- isSoldOut이 true → <SalesBadge /> 반환
- isSoldOut이 undefined → undefined 반환

undefined는 falsy이기 때문에 단락 평가에 의해 undefined가 그대로 반환된다.
React는 undefined를 렌더링하지 않기 때문에 결과적으로 아무것도 보이지 않게 된다.

---

### 해결 방법 (?? 연산자)
```tsx
{isSoldOut ?? <SalesBadge isSoldOut={isSoldOut} />}
```

?? 연산자는 다음과 같이 동작한다.
- null 또는 undefined → 오른쪽 값 반환
- 그 외 → 왼쪽 값 반환

즉, undefined ?? <SalesBadge /> → <SalesBadge /> 이므로 정상적으로 렌더링된다.

---

&& vs ??

| 연산자 | 조건 | 반환값 |
|--------|------|--------|
| && | falsy면 | 왼쪽 값 |
| && | truthy면 | 오른쪽 값 |
| ?? | null/undefined면 | 오른쪽 값 |
| ?? | 그 외 | 왼쪽 값 |

👉 && : 조건부 렌더링
👉 ?? : 기본값 처리 (fallback)

---

### 회고

그동안 &&를 단순한 조건문처럼 사용했지만, 실제로는 "값을 반환하는 연산자"라는 점을 놓치고 있었다.
특히 undefined가 그대로 반환되면서 React에서 아무것도 렌더링되지 않는다는 점이 깨달았다.
PR 리뷰를 통해 단락 평가뿐만 아니라 얕은 비교(shallow compare)에 대해서도 다시 고민해볼 수 있었다.
