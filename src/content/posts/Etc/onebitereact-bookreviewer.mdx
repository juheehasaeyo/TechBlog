### ❗ 여기서 문제
1. **let, var, const의 차이?** <italic>p,16, 66 참고</italic><br />
let은 var와 달리 중복 선언이 불가능하며, let과 var는 변수지만 const는 상수이다. 
변수는 선언과 동시에 할당하는 초기화 과정이 필요치 않지만 상수는 필요하다.
var는 함수 스코프, let과 const는 블록 스코프이다.

2. **함수 Number와 parseInt의 차이?** <italic>p.29 참고</italic><br />
Number는 문자열을 숫자로 변환해서 반환한다.
```tsx
// 숫자가 아닌 문자를 포함한 문자열은 NaN을 반환함
let strA = '10';
let strB = '10개';

let numA = Number(strA);
let numB = Number(strB);

console.log(numA); // 10
console.log(numB); // NaN
```
parseInt는 괄호 안에 두 개의 값을 콤마로 구분해서 전달하는데, 첫 번째 값은 변환하려는 문자열이고 두 번째 값은 진수이다.
```tsx
// 문자열이 숫자가 아닌 문자로 시작하면 NaN을 반환함
let str = '화이팅 2026';
let num = parseInt(str, 10); 

console.log(num); // NaN
```

3. **비교연산자 == 과 === 의 차이?** <italic>p.36 참고</italic><br />
== 는 값만 비교할 뿐 자료형은 비교하지 않는다.
```tsx
let numA = 2;
let numB = 2;
let numC = '2';

console.log(numA === numB); // true
console.log(numB === numC); // false
console.log(numA == numC); // true
```
4. **인수와 매개변수의 차이?** <italic>p.53 참고</italic><br />
인수는 함수를 호출하면서 넘겨주는 값이고 매개변수는 함수에서 넘겨받은 인수를 저장하는 변수이다.
즉, 인수는 '값', 매개변수는 그 값을 저장할 '변수'로 생각하면 이해가 쉽다.
```tsx
funtion getArea(width, height) {
let area = width * height;
console.log(area);
}

getArea(10, 20); // 에서 10과 20이 인수, width와 height가 매개변수
```

5. **호이스팅은 선언이 끌어올려지는 것이다?** <italic>p.55 참고</italic><br />
X. 끌어올려지는 것처럼 보이는 현상이다.<br />
호이스팅: 변수나 함수를 호출하거나 접근하는 코드가 함수 선언보다 위에 있음에도 불구하고, 마치 선언 코드가 위에 있는 것처럼 동작하는 방식이다.<br />
자바스크립트는 코드를 실행하기 전 준비 단계에서 중첩 함수가 아닌 함수들을 모두 찾아 미리 생성해두기 때문에 함수 선언 코드를 호출보다 늦게 작성해도 자연스럽게 호출할 수 있다.
```tsx
func();

function func() {
console.log('Hello'); // Hello
}
// 함수 func에 대한 선언이 호출코드보다 아래에 있지만 호출보다 먼저 함수를 선언한 것처럼 동작한다.
```

6. **truthy falsy 단락평가(Short-circuit Evaluation)**<italic>p.81 참고</italic><br />
falsy한 값이란 boolean 자료형의 false값은 아니지만, 거짓과 같은 의미로 쓰이며 조건식에서 거짓(false)로 평가되는 것을 말한다. falsy 값은 다음 7가지이다.
- undefined
- null
- 0, -0
- NaN
- "" (빈 문자열)
- 0n (BigInt)

단락평가 부분을 읽으며 프로젝트에서 얕은 비교와 단락평가에 대해 찾아보면 좋겠다는 리뷰를 받은 적이 있어서 기억났다. 해당 부분과 함께 다시 리마인드 해보자!

단락평가는 논리 연산에서 첫 번째 피연산자의 값만으로 해당 식의 결과가 확실할 때, 두 번째 값은 평가하지 않는 것을 말한다.
예를 들어 true || false 비교식에서 첫 번째 피연산자의 값이 true이므로 두 번째 피연산자의 값이 무엇이든 연산 결과는 true이다. 또한 false && true와 같은 식은 첫 번째 피연산자의 값이 false 이므로 두 번째 피연산자가 무엇이든 연산 결과가 false인 경우가 있다.

논리 연산자 &&는 단순히 boolean이 아니라 "값"을 반환한다.

A && B
- A가 falsy → A 반환 (뒤를 평가하지 않음)
- A가 truthy → B 반환

즉, A가 false면 B를 볼 필요가 없기 때문에 A를 그대로 반환하고, A가 true면 B까지 평가한 뒤 B를 반환한다.
---
프로젝트에서의 문제 상황

다음과 같은 코드를 사용하고 있었다.
```tsx
{isSoldOut && <SalesBadge isSoldOut={isSoldOut} />}
```

이 코드는 isSoldOut이 truthy일 때만 컴포넌트를 렌더링한다.
하지만 isSoldOut이 undefined인 경우, 기대와 다르게 컴포넌트가 렌더링되지 않았다.

왜 이런 일이 발생했을까?!
```tsx
isSoldOut && <SalesBadge />

- isSoldOut이 true → <SalesBadge /> 반환
- isSoldOut이 undefined → undefined 반환
```
undefined는 falsy이기 때문에 단락 평가에 의해 undefined가 그대로 반환된다.
React는 undefined를 렌더링하지 않기 때문에 결과적으로 아무것도 보이지 않게 된다.


해결 방법은 **?? 연산자** 사용하기!
```tsx
{isSoldOut ?? <SalesBadge isSoldOut={isSoldOut} />}
```

?? 연산자는 다음과 같이 동작한다.
- null 또는 undefined → 오른쪽 값 반환
- 그 외 → 왼쪽 값 반환

즉, 
```tsx
undefined ?? <SalesBadge /> → <SalesBadge />
```
이므로 정상적으로 렌더링된다.

그렇다면 && vs ?? 차이를 정리해보자

| 연산자 | 조건 | 반환값 |
|--------|------|--------|
| && | falsy면 | 왼쪽 값 |
| && | truthy면 | 오른쪽 값 |
| ?? | null/undefined면 | 오른쪽 값 |
| ?? | 그 외 | 왼쪽 값 |

👉 && : 조건부 렌더링<br />
👉 ?? : 기본값 처리 (fallback)
---
그동안 &&를 단순한 조건문처럼 사용했지만, 실제로는 "값을 반환하는 연산자"라는 점을 놓치고 있었다.
특히 undefined가 그대로 반환되면서 React에서 아무것도 렌더링되지 않는다는 점이 깨달았다.
PR 리뷰를 통해 단락 평가뿐만 아니라 얕은 비교(shallow compare)에 대해서도 다시 고민해볼 수 있었다.

7. **메서드** 정리 <italic>p.102 참고</italic><br />

pop() : 배열의 맨 끝 요소를 제거하고 제거한 요소를 반환하는 메서드. 빈 배열에서 pop 메서드를 사용하면 제거할 요소가 없기 때문에 undefined를 반환한다.<br />
push() : 배열 맨 끝에 요소를 추가하고 새로운 길이를 반환하는 메서드<br />
shift() : 배열의 맨 앞 요소를 제거하고 제거한 요소를 반환하는 메서드(pop 메서드와 반대)<br />
unshift() : 배열 맨 앞에 요소를 추가하고 새 배열의 길이를 반환하는 메서드(push 메서드와 반대)<br />
slice(start, end) : 기존 배열에서 특정 범위를 잘라 새로운 배열을 반환함. 이 때 원본 배열은 수정되지 않는다!<br />
```tsx
const arr = [1, 2, 3];
const sliced = arr.slice(0, 2);

console.log(arr); // [1, 2, 3]
console.log(sliced); // [1, 2]
```
concat() : 서로 다른 배열을 이어 붙여 새 배열을 반환한다
```tsx
let arrA = [1, 2];
let arrB = [3, 4];
let arrC = arrA.concat(arrB);

console.log(arrC); // [1, 2, 3, 4]
```

여기까지는 1 ~ 3장을 읽으며 개념 리마인드 한 부분이다.
