Next.js에서 SVG를 컴포넌트로 사용하기 위해 `@svgr/webpack`을 설치했다.
SVG의 색상을 동적으로 변경하기 위해 적용한 설정이었지만, 예상치 못한 문제가 발생했다.
그 후 next.config.ts를 next.config.mjs로 변경하고 아래 설정을 추가했다.

```bash
npm install @svgr/webpack
# 또는
yarn add @svgr/webpack
```

```js
webpack: (config) => {
        config.module.rules.push({
            test: /\.svg$/,
            use: ["@svgr/webpack"],
        });

        return config;
    },
```
이 설정을 적용한 직후, 기존에는 잘 작동하던 Image 태그에서 갑자기 에러가 발생했다.
```Error: Image with src "/assets/icons/ic_ticket.svg" is missing required "width" property.```

![에러 캡쳐본](/images/posts/Dev/clonecoding-review/Image에러창_캡쳐.png)

Image 태그에는 **width** 속성이 필요한데, **width** 속성이 없다는 내용이 나타난다.

### 사건의 발단: NavBar의 SVG 아이콘
CGV 웹사이트 클론코딩을 하면서 NavBar의 navItems에 들어갈 SVG 아이콘을 컴포넌트 형태로 사용하기 위해 SVGR을 도입했다.
![svg 컴포넌트화 캡쳐본](/images/posts/Dev/clonecoding-review/svg컴포넌트화.png)

SVGR 적용 전에는 아래처럼 Image 태그에 SVG 경로만 넣어도 정상적으로 렌더링되었다.
하지만 SVGR을 적용한 이후에는 같은 코드에서 width와 height가 없다는 에러가 발생했다.
![Image태그 캡쳐본](/images/posts/Dev/clonecoding-review/Image태그_너비높이_없을때.png) 

필수 속성인 width와 height를 주지 않아서 뜬 에러였다. 근데? Image 태그는 src, alt만 필수로 알고 있는데요!?

### 이유: SVG가 더 이상 '이미지 파일'이 아니다
SVGR을 적용하면 SVG는 다음과 같이 동작 방식이 바뀐다.
기존에는 정적 파일을 import하면 Next.js가 이미지 메타데이터에서 자동으로 크기를 추론해 주지만,
SVG가 React 컴포넌트로 변환되면서 이 기능이 더 이상 작동하지 않는다.

또한 SVG에 fill을 사용하면 부모 요소를 기준으로 꽉 채우는 방식이기 때문에
오히려 width/height를 지정하는 것이 불가능해진다.
즉, Next.js는 SVG를 정적 파일(static image) 로 인식하지 못한다.


### 해결방법
1. Image 태그에 width/height 수동 지정

```tsx
<Image
  src="/assets/icons/ic_ticket.svg"
  alt="예매 티켓"
  width={24}
  height={24}
/>
```

2. SVG를 바로 컴포넌트로 import하여 사용
```tsx
import IcTicket from "@/assets/icons/ic_ticket.svg";

export default function NavItem() {
  return <IcTicket width={24} height={24} />;
}
```

Image 태그는 fill 속성을 사용할 때만 width, height를 생략할 수 있기 때문에, 그 외의 경우에는 width, height 값을 지정해 주어야 한다.

정리하면, Image 컴포넌트는 fill 속성을 사용할 때만 width와 height를 생략할 수 있으며, 그 외의 경우에는 반드시 두 값을 지정해야 한다.
그리고 SVGR 적용 이후에는 SVG가 더 이상 정적 이미지 파일이 아니라 React 컴포넌트로 변환되기 때문에, Next.js가 자동으로 크기를 추론할 수 없어 width와 height를 반드시 명시적으로 지정해야 한다.
